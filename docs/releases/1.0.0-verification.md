These checks verify a release candidate, not an already-published APK.

## Completed checks

- [Android CI, attempt 2](https://github.com/openonion/openonion-messages-android/actions/runs/33571129432/attempts/2):
  unit tests, lint, debug/release builds, and API 35 emulator tests passed.
- [Release preflight](https://github.com/openonion/openonion-messages-android/actions/runs/33607376138):
  minified APK/AAB builds, application metadata, signatures, checksums, and
  release-note validation passed. This used an ephemeral CI-only certificate
  and intentionally published nothing.
- Local JDK 17 build: `./gradlew test lint assembleDebug assembleRelease`
  succeeded.
- Forced local execution:
  `./gradlew connectedDebugAndroidTest testDebugUnitTest testReleaseUnitTest --rerun-tasks`
  succeeded on an Android 16 / API 36 ARM64 emulator. Each unit-test variant
  passed 11 tests. The connected suite passed five tests and skipped the three
  backend-specific methods, which require the separate lifecycle gate below.
- `./scripts/verify-emulator-sms.sh` installed the debug app, granted the
  default-SMS role on the dedicated emulator, injected a synthetic SMS, and
  verified its presence in Android's SMS provider. No real SMS was used.
- The app displayed the synthetic SMS in its inbox. Deletion through the
  visible confirmation dialog removed that message from the SMS provider;
  a query scoped to the test message returned no result.

## Publication gate

At the time of these checks, no Android release tag or public GitHub Release
exists. Durable signing-key configuration still requires owner authorization.
Do not distribute the ephemeral preflight build as a release or mistake a
successful manual workflow run for publication.

After publishing, additionally verify the public APK checksum, build
attestation, package/version metadata, and durable certificate fingerprint.
Install the downloaded APK and smoke-test SMS receipt on a dedicated emulator
or test device before declaring the published artifact verified.
